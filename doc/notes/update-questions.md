# 更新作業の前に聞いておくこと

自分用の確認メモ。分かっていることを聞き直さず、まず過去の手順書を見て、不明なところを確認する。
ここには質問だけを残す。回答に含まれる社内情報、実際の構成や接続先、手順書の内容は会社指定の場所に記録する。

## 最初に確認したいこと

- [ ] 今回の対象に使う過去の手順書はどれか。最新版の保存先と、今回変更する箇所を教えてもらう。
- [ ] 更新はCloudFormationコンソールから、修正したテンプレートで変更セットを作り、確認後に実行する流れで合っているか。パラメータで指定する項目もあるか。
- [ ] 作業者・確認者・承認者は誰か。作業開始と完了はどこに連絡するか。
- [ ] 対象一覧はどこにあるか。「1台」がDBインスタンス、クラスター、Redisのノード、レプリケーショングループのどれを指すか。
- [ ] 対象ごとの現在のバージョンと更新先は何か。マイナー更新だけか、メジャー更新も含むか。

## Terraformのstateとの比較について

聞き取れなかったので、ここは言葉だけで判断せず、手順書のコマンドを見せてもらう。

> 更新後の差分確認は、Terraformのstateと実環境の比較でしょうか。それともCloudFormationのドリフト検出でしょうか。手順書の該当箇所を教えていただけますか？

- [ ] Terraformを使う場合、管理対象はDB・Redis本体なのか、CloudFormationスタックなのか。それぞれどのツールを正として管理するか。
- [ ] 比較に使うコマンドやツールは何か。通常のplan、refresh-only、保存したファイル同士の比較など、実際の手順を確認する。
- [ ] 確認に使うディレクトリ、workspace、backend、AWSアカウント・リージョンはどれか。
- [ ] 想定される差分は何か。想定外の差分があったら誰に確認するか。
- [ ] 差分を見るだけか、stateの更新まで行うか。Terraformコードの修正も必要か。担当者と実施順序はどうなっているか。

## Redisの更新前に行う設定

「オートスケーリング」という説明の意味を確認する。自動フェイルオーバーと同じものとして扱わない。

> 更新前の設定は、レプリカを追加してMulti-AZと自動フェイルオーバーを有効にする、という理解で合っていますか？ Auto Scalingの設定も別途必要でしょうか？

- [ ] 現在のクラスターモード、シャード数、レプリカ数、AZ配置、自動フェイルオーバーの設定はどうなっているか。
- [ ] 事前の構成変更もCloudFormationで行うか。構成変更とエンジン更新は別々の変更セットで実施するか。
- [ ] レプリカ追加後、同期完了や正常性を何で確認してから更新に進むか。
- [ ] フェイルオーバー時の接続断とアプリの再接続は検証済みか。更新中の停止・影響はどこまで許容されているか。
- [ ] 更新後も追加したレプリカなどを維持するか。元に戻す場合の担当者、タイミング、手順はあるか。

## RDS・Auroraの更新

- [ ] エンジンの種類、Single-AZ／Multi-AZ、Auroraのライター・リーダー構成を対象ごとに確認できるか。
- [ ] パラメータグループやオプショングループも変更するか。再起動が必要な設定はあるか。
- [ ] 更新の実施タイミングは即時か、メンテナンスウィンドウか。保留中の別の変更はないか。
- [ ] 互換性やアプリの接続確認はどこまで済んでいるか。検証環境がない対象はどう事前確認するか。

## GitHub・SVNでのファイル管理

- [ ] 対象ごとのリポジトリ、ディレクトリ、テンプレート、パラメータファイルはどれか。
- [ ] GitHub側とSVN側で管理が分かれている理由は、構築時期や担当チームの違いか。
- [ ] GitHubはブランチ・PR・レビューを使うか。SVNはどの場所から取得して、どの手順でレビュー・commitするか。
- [ ] テンプレートの登録・承認・実環境への反映はどの順序で行うか。
- [ ] 実行したテンプレートとGitのコミットID／SVNのリビジョン番号をどう対応付けるか。
- [ ] 更新に失敗した場合、リポジトリ側の変更はどのように扱うか。

## 当日の確認・復旧・証跡

- [ ] 作業前バックアップは何を、いつ取得するか。取得完了と復元可能性の確認方法はあるか。
- [ ] 変更セットで許容する変更は何か。置換・削除や予定外の変更が出た場合の中止基準はあるか。
- [ ] 停止可能時間、待機時間の上限、作業中止・復旧へ切り替える判断基準は何か。
- [ ] バージョンを戻せない場合を含め、復旧はスナップショットからの再作成など、どの方法で行うか。接続先の切り替え担当は誰か。
- [ ] CloudFormationのロールバックと、DB・Redisの復旧をどう切り分けるか。
- [ ] 更新後に見るログ・メトリクス・アラームは何か。アプリ側の動作確認担当と完了条件は決まっているか。
- [ ] 画面キャプチャ、イベント、変更セット、バージョン確認結果など、必要な証跡と保存先はどこか。
- [ ] 作業後、どれくらい監視して完了とするか。翌日の確認や引き継ぎはあるか。
